# VK-бот туров

Бот отвечает в личных сообщениях сообщества карточкой одного тура или подборкой из нескольких туров. Источник истины — таблица `tour_sheets`, которую обновляет существующий XML-фид `https://vs-travel.ru/prices/tours.xml`.

Бот не хранит лиды, контакты, историю диалога или состояние пользователя. Единственная исходящая цель кроме страницы тура — подписка на рассылку `https://vk.ru/app5898182_-53145183#s=3819494`.

## Callback API

Публичные адреса (одинаковое поведение):

- `POST /vk/callback`
- `POST /api/vk/callback`

Переменные окружения:

- `VK_BOT_GROUP_ID=223347696`
- `VK_BOT_SUBSCRIPTION_URL=https://vk.ru/app5898182_-53145183#s=3819494`
- `VK_BOT_TOKEN` — ключ сообщества с правом отправлять сообщения
- `VK_BOT_SECRET` — секрет Callback API
- `VK_BOT_CONFIRMATION_CODE` — строка подтверждения сервера
- `VK_BOT_API_VERSION=5.199` — опционально
- `VK_BOT_TOUR_URL=https://vs-travel.ru/tour?id=` — опционально

Без трёх секретных значений endpoint отвечает `503` и ничего не отправляет.

## Как передать ключи

Ссылка для поста с одним туром:

```text
https://vk.me/club223347696?ref=tour%3A512&ref_source=post
```

Ссылка с группой туров:

```text
https://vk.me/club223347696?ref=tours%3A512%2C603&ref_source=post
```

Переход открывает личный диалог с сообществом. Само открытие окна не создаёт событие Callback API: карточки отправляются после того, как турист нажмёт «Начать» или отправит первое сообщение. В этом `message_new` VK передаёт `object.message.ref`, и бот получает ключи без отдельного хранилища токенов.

Обработчик принимает:

- текст `512` или `тур 512`;
- группу `512,603`;
- `ref` вида `tour:512` или `tours:512,603`;
- payload кнопки `{"tour_key":"512"}`;
- payload группы `{"tour_keys":["512","603"]}`.

За один ответ выводится не больше девяти туров, чтобы вместе с кнопкой подписки уложиться в лимит клавиатуры VK.

## Сквозной тест

Реальный ключ из фида: `512`.

Ожидаемая карточка:

```text
Незнакомая Кострома                      (жирным, через format_data)
Маршрут: Кострома – Закулисье театра им. Островского – Костромской ювелирный завод (проезд на ж/д экспрессе «Ласточка»)
Продолжительность: 1 день
Стоимость: от 5 500 ₽
```

Ссылки в тексте нет: страница тура и подписка — кнопками. Фото — обложка `og:image` со страницы тура
(в `tours.xml` фото нет), загружается в сообщение через `photos.getMessagesUploadServer`; для этого ключу
сообщества нужно право «Фотографии». Без него карточка уходит без фото, в журнал пишется `no photo for tour`.

Открытие ссылки `vk.me/...?ref=` само по себе событий не создаёт. Ключи из `ref` приходят с первым
действием туриста: кнопкой «Начать» (VK показывает её только в новом диалоге) или любым сообщением.

Локальная проверка без настоящего ключа VK:

```bash
node --test server/vk-tour-bot.test.mjs
```

Тест проходит весь внутренний путь: событие `message_new` → ключ `512` → запрос к `tour_sheets` → карточка → тело `messages.send`. Вызов VK подменён тестовым транспортом, поэтому секрет и доступ к сообществу не требуются.

## Мини-приложение: подборка по ссылке

Ссылка для поста: `https://vk.com/app54794214#tours=512,603` (один тур — `#tours=512`, до девяти номеров).

VK открывает `https://mbox.shar-os.ru/vk/app` (`server/vk-app.html`), страница берёт номера из `#` и запрашивает
`GET /vk/app/tours?tours=512,603`. Сервер отдаёт из `tour_sheets` только туры в продаже: название, маршрут,
продолжительность, цену, ссылку на страницу тура и обложку (`og:image` со страницы тура, кешируется в памяти процесса).
Страница показывает карточки с кнопкой «Перейти» и внизу «Подписаться на рассылку». Сообщения не отправляются,
подпись запуска не нужна — туры публичные.

Настройки приложения (dev.vk.com → «Размещение»): во всех полях URL и «Режим разработки» —
`https://mbox.shar-os.ru/vk/app`, состояние «Включено».
