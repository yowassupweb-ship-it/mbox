# Корпоративная версия программы тура (route-compressor-corp)

Навык для старших моделей (Claude, Codex). Вход — номера туров (те же, что в адресе `vs-travel.ru/tour?id=<номер>`). Выход на каждый тур — HTML-страница для копирования в менеджерку и HTML-документ в MBOX (артефакт в разделе «Маршруты» проекта «Вокруг света»). Word-файлы не генерируются: результатом считается HTML. Скрипты делают механику: скачать страницу тура с сайта, вычистить время и цены, проверить текст, собрать страницу, положить результат в MBOX. **Текст пишет модель** — это главная и самая ответственная часть работы.

## Где что лежит

- **Папка навыка** — каталог этого SKILL.md: у Claude `~/.claude/skills/route-compressor-corp`, у Codex `~/.codex/skills/route-compressor-corp`. В ней `rules.md` и `scripts/`. Ниже `<навык>` — эта папка. Ссылки вида «§4.1» ведут в [rules.md](rules.md).
- **Навык хранится на сервере MBOX** (`skills/route-compressor-corp` в репозитории MBOX) и ставится оттуда синхронизацией (`scripts/sync-skills.mjs`, наблюдатели MBOX делают это сами). Установленная копия перезаписывается: правила и скрипты меняй в репозитории MBOX, затем коммит и деплой.
- **Рабочая папка** `<данные>` — `%USERPROFILE%\Desktop\Mbox\route-compressor-corp` (или переменная окружения `ROUTE_COMPRESSOR_CORP_HOME`). Если уже существует старая папка `route-operator-skill` или задана `ROUTE_OPERATOR_HOME`, скрипты используют её для совместимости. В рабочей папке лежат скачанные туры, тексты и готовые страницы `out/`. Логинов и паролей навыку не нужно: страница тура на сайте публичная.

## Пять правил, которые нельзя нарушать

1. **Ничего не сочинять.** Каждый факт — только из текста тура на сайте (страница `vs-travel.ru/tour?id=<номер>`). Сжатие — выбор и сокращение фраз источника, а не пересказ своими словами и не общие знания модели (§1).
2. **Источник — только страница этого тура на vs-travel.ru.** Не добавляй данных с других страниц, сайтов и из общих знаний. Менеджерская программа как источник не нужна — в неё результат только вставляют.
3. **Результат для человека — только HTML** из `<данные>/out/ready/`. Word-файлы не генерируются; Markdown в `out/work/` — рабочий файл, его человеку не отдают.
4. **Текст показывает, ради чего ехать, фактами.** Сначала самое интересное из оригинала, потом главное, практическое — последним и коротко. Никакого времени, цен, анонсов, места сбора, оценочных слов (§2, §4).
5. **Каждая правка — запись в «Истории изменений»**, каждое подтверждённое владельцем общее правило — в rules.md (в репозитории MBOX) и в MBOX-память.

## Перед первым запуском

- Node.js 18 или новее (`node -v`).
- Интернет: скрипт скачивает страницу `https://vs-travel.ru/tour?id=<номер>` (адрес сайта можно переопределить переменной `ROUTE_SITE_URL`). Ни VPN, ни доступа к менеджерке не нужно.
- Самопроверка скриптов (без сети, несколько секунд):

  ```powershell
  node "<навык>\scripts\selftest.mjs"
  ```

  Должна закончиться строкой `selftest: все проверки пройдены`. Если нет — скрипты сломаны: сначала почини их в репозитории MBOX, туры не делай.

## Работа по шагам

### Шаг 0. Контекст

1. Прочитай [rules.md](rules.md) **целиком** — каждый раз, даже если кажется, что помнишь. Правила меняются по замечаниям владельца.
2. MBOX, проект «Вокруг света»: `get_agent_context`; `search_memory("route-compressor-corp route-to-operator")` — свежие и исторические замечания владельца по навыку; `search_memory("Редакционная политика")` — полный текст редполитики (запись #136, выжимка — §4.5). Если MBOX недоступен, скажи об этом и работай по rules.md.
3. Если по задаче есть todo в MBOX — `claim_task`.

### Шаг 1. Черновики

```powershell
node "<навык>\scripts\route.mjs" 1596 2196
```

Номера бери из сообщения (число, ссылка `vs-travel.ru/tour?id=1596` или старая ссылка `/tours/1596/edit` — номер тот же). Для каждого тура скрипт скачивает страницу тура с сайта, сохраняет `<данные>/out/tour-<ID>.json` и пишет черновик `<данные>/out/work/tour-<ID>-draft.md`. Пока текста `out/work/tour-<ID>.md` нет, скрипт пишет «текста ещё нет» — это нормально.

Черновик — полная программа по дням: `### N. [тип] Заголовок` и полный текст пункта. Время, цены и название тура уже вырезаны. Если у пункта на сайте нет заголовка, а описание начинается жирной строкой, эта строка стала заголовком. Пометки в скобках подсказывают: `время 07:00 убрано`, `место сбора группы — не переносить`, `рекламных фраз: 2`. Строки `ВНИМАНИЕ:` — ошибки в данных (например, ночей больше, чем дней). Внизу — «Включено» и другие разделы (только для справки) и список того, что скрипт убрал.

### Шаг 2. Текст — главная работа

Пиши `<данные>/out/work/tour-<ID>.md` в UTF-8 (в PowerShell не используй `Set-Content` без `-Encoding utf8`). Формат — §5. По каждому пункту программы:

1. Прочитай **весь** текст пункта в черновике.
2. Отметь, что человек перескажет знакомому: поворот или загадку, рекорд, число, связь с кино или известным именем, образ или прозвище из источника, судьбу места, что турист сделает сам (§4.2, §4.3).
3. Напиши жирное название (заголовок пункта без рекламного подзаголовка) и описание в порядке **мотивация → главное → практическое** (§4.1).
4. Убери время, цены, анонсы, место сбора, оценки, штампы (§2, §4.5). Отличительные детали — конфессию, век, материал, имя, место — ради длины не режь (§4.4).
5. Сверь каждое предложение с черновиком: тот же факт, тот же объект, те же числа, те же «первый / единственный / крупнейший» (§1).

Служебные пункты (еда, переезд, размещение) — короткими строками, подряд идущие — одним абзацем (§3.5). В конце файла — `**История изменений**` с записью о сделанном (§6).

### Шаг 3. Проверка и сборка

```powershell
node "<навык>\scripts\route.mjs" 1596 2196 --no-fetch
```

`--no-fetch` не ходит на сайт и берёт уже скачанные данные. `--open` откроет готовые страницы в браузере. Вывод бывает трёх видов:

| Вывод | Что значит | Что делать |
| --- | --- | --- |
| `текст нарушает правила — исправь …` и список | Страница **не собрана**: время, цена, анонс, название тура, место сбора, число / век / имя, которых нет на странице тура, стоп-слово редполитики, нет или не обновлена история изменений | Исправь каждую строку, запусти снова |
| `Длиннее ориентира …`, `Практическое перевешивает мотивацию …` | Страница собрана, это подсказка | Перестрой порядок, сократи второстепенное. Отличительные детали и богатое описание места не режь |
| `Слова не из источника …` | Страница собрана; эти слова взяты не из источника | Пройди каждое: если смысл изменился или добавлен факт — верни формулировку источника |

Повторяй, пока нет ошибок и каждое предупреждение разобрано осознанно.

### Шаг 4. Самопроверка перед ответом

Пройди чек-лист §8 по каждому туру. Самые частые ошибки: факт не из черновика, практическое впереди мотивации, вырезанная ради длины деталь, забытая запись в истории.

### Шаг 5. Ответ человеку

- Пути к странице `<данные>\out\ready\tour-<ID>.html` (полным путём). Word-версию не предлагай: владельцу нужен только HTML. Markdown-файлы не предлагай.
- Номер артефакта MBOX по каждому туру: `route.mjs` печатает строку «MBOX: создан/обновлён артефакт «Маршруты» #<id>». Артефакт — тот же HTML-документ в консоли MBOX: открывается вкладкой `file:<id>`.
- Работаешь из консоли MBOX — открой человеку результат сам: MCP `open_tab` с `target: "path:<полный путь к папке out\ready>"` (папка раскроется в «Папках» MBOX Desktop) или `path:<полный путь к tour-<ID>.html>` для одного тура. Ответ «No open MBOX window» — просто дай пути текстом.
- По 3–6 строк на тур: что было спорным в данных (пустое название дня, ночей больше, чем дней, битые века), какие яркие факты вынесены, где ориентир длины превышен сознательно.
- Если что-то не получилось (нет доступа, пустая программа) — скажи прямо, не заполняй пробел.

### Шаг 6. MBOX

`record_memory` (проект «Вокруг света», теги `route-compressor-corp`): номера туров, пути к страницам, спорные места, принятые решения. Если была задача — `set_task_status` (обычно `review`).

## Когда владелец присылает правку

1. Исправь текст в `<данные>/out/work/tour-<ID>.md`. **Сверху** в «Истории изменений» — запись: дата, что было, что стало, почему.
2. Пересобери с `--no-fetch`. Без новой записи в истории скрипт страницу не соберёт.
3. Реши, частный это случай или общее правило. Общее правило допиши в `skills/route-compressor-corp/rules.md` **в репозитории MBOX** — в свой раздел с примером «было → стало» и строкой в §10. Если его можно поймать механически — добавь шаблон в `AWKWARD` или `EDITORIAL` в `scripts/route.mjs` и случай в `scripts/selftest.mjs`, запусти selftest. Затем коммит и деплой MBOX — так правило получат все агенты.
4. Проверь то же правило в остальных турах текущей работы и поправь сразу.
5. `record_memory` с тегами `route-compressor-corp`, `editorial-policy`, `feedback`: правило одной-двумя фразами, откуда взялось, как применять.

Не выполняй замечание в обход принципов: нельзя резать отличительную деталь, чтобы уложиться в длину; нельзя переносить факт на другой объект, чтобы снять противоречие; нельзя добавлять эмоцию словами, которых нет в источнике.

## Документ в MBOX и HTML

Готовый тур — это HTML-документ, а документы живут в MBOX, а не только в папке на диске. После успешной сборки `route.mjs` кладёт страницу тура артефактом в раздел **«Маршруты»** проекта «Вокруг света» — имя `Тур <ID> — <маршрут>.html`.

Имя артефакта закреплено за номером тура: пересборка обновляет тот же документ и поднимает версию (`v1` → `v2`), копии не плодятся.

Word-версия для этой задачи не нужна и больше не создаётся. Если рядом остались `.docx` от старых запусков, не считай их результатом, не открывай и не предлагай владельцу: отдавай только HTML.

Навыку нужны переменные окружения `MBOX_URL` и `MBOX_PASSWORD` (те же, что у наблюдателей MBOX); имя проекта можно переопределить `ROUTE_CORP_PROJECT`. Без них сборка не падает: HTML готов, а в выводе появляется строка «Артефакт MBOX не сохранён: …» — её и передай человеку.

## Если что-то пошло не так

| Симптом | Что делать |
| --- | --- |
| Таймаут или `ENOTFOUND vs-travel.ru` | Нет интернета или сайт не отвечает — скажи прямо, данные тура не выдумывай |
| `на … нет страницы тура — проверьте номер` | Тура с таким номером на сайте нет (снят или опечатка) — уточни номер у человека |
| Сайт недоступен, а тур нужен | Попроси человека открыть страницу тура в браузере, нажать Ctrl+S и прислать путь к файлу; затем `node "<навык>\scripts\fetch-tour.mjs" --from-html <файл.html> <ID>` и шаг 1 с `--no-fetch` |
| `в данных тура нет программы по дням` | На странице тура нет программы по дням (или сайт поменял разметку — тогда чини разбор в `fetch-tour.mjs`) — сообщи человеку, текст не сочиняй |
| `Артефакт MBOX не сохранён: …` | HTML собран, в MBOX не ушло. Причина в той же строке: нет `MBOX_URL`/`MBOX_PASSWORD` в окружении, не отвечает сервер, не найден проект «Вокруг света». Скажи человеку прямо и отдай HTML |
| `пустое поле «Маршрут»` | В туре не заполнен маршрут — спроси человека, каким должен быть заголовок |
| `текст изменился, а история изменений — нет` | Добавь сверху запись в «Историю изменений» |
| `обрыв текста (§1)` | Описание обрезано по первой точке, а она стояла внутри инициалов или сокращения — допиши фразу до конца по черновику |
| `битое слово «…» — в источнике «…»` | Слово потеряло первую букву при записи файла — верни слово источника и перечитай весь текст: такие сбои идут пачками |
| `нет строки продолжительности` / `дефис вместо тире` | Вторым абзацем — строка из черновика («3 дня / 2 ночи»); места в маршруте разделяются « – », не дефисом |
| `служебная строка жирным заголовком` / `точка в конце жирного названия` | Завтрак, размещение, свободное время — строки группы §3.5, а не пункты; у названия пункта точки в конце нет |
| Навыка нет в `~/.claude/skills` или он устарел | `node scripts/sync-skills.mjs` из репозитория MBOX (нужны `MBOX_URL`, `MBOX_PASSWORD`); без установки SKILL.md и rules.md читаются через MCP `get_skill` |
| Стоп-слово сработало на нормальной фразе | Перефразируй. Если шаблон явно ошибочен — сузь его в `route.mjs` в репозитории MBOX, добавь случай в selftest, запусти selftest, выкати |
