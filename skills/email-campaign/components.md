# Каталог блоков рассылки «Вокруг света»

Источник всех блоков — `letter1.html`. Это не набор эскизов: каждый блок уже использован в рабочем письме, использует таблицы и адаптирован к ширине 660 px. При сборке копируй нужный блок из исходника, меняя только его контент, ссылки, изображения, `alt` и UTM.

## Номера блоков

`B01 shell`, `B02 header-nav`, `B03 intro`, `B04 primary-cta`, `B05 divider`, `B06 section-title`, `B07 tour-card-left`, `B08 tour-card-right`, `B09 catalog-banner`, `B10 messenger-promo`, `B11 bottom-nav`, `B12 footer`.

Эти номера используются в MBOX, брифе и [визуальной библиотеке](library.html). Они не означают, что необязательный блок должен появиться в письме.

## Постоянная оболочка — не редактировать

| ID | Блок | Назначение |
| --- | --- | --- |
| `shell` | DOCTYPE, `<head>`, CSS, preheader, внешний фон и контейнер `.em-narrow-table` | Брать целиком из `letter1.html`; не заменять на современную div-вёрстку и не удалять мобильные классы. |
| `footer` | Серый подвал с адресом, телефоном, почтой и социальными иконками | Сохранять в каждом маркетинговом письме. `mailto:` и `tel:` не размечать UTM. |

## Блоки, из которых собирается письмо

| ID | Что видит получатель | Данные от SMM | Когда ставить |
| --- | --- | --- | --- |
| `header-nav` | Логотип и 4 кнопки разделов | Обычно ничего; при необходимости только ссылки меню | В начале всегда |
| `intro` | Оранжевый заголовок и вводный текст | Заголовок, 1–2 коротких абзаца | В начале всегда |
| `primary-cta` | Одна большая оранжевая кнопка | Текст кнопки, URL | Только если есть один главный переход |
| `divider` | Тонкий разделитель | Ничего | Между крупными секциями |
| `section-title` | Оранжевый заголовок подборки | Название секции | Перед группой карточек |
| `tour-card-left` | Карточка: изображение слева, текст справа | Изображение, alt, название, маршрут, длительность/дата, текст CTA, URL | Нечётные карточки подборки |
| `tour-card-right` | Та же карточка, но изображение справа | Те же 7 полей | Чётные карточки: чередовать с `tour-card-left` |
| `catalog-banner` | Большой баннер с изображением, белым текстом и кнопкой | Изображение, alt, заголовок, описание, CTA, URL | Финальный общий призыв к действию |
| `messenger-promo` | Оранжевая карточка подписки на Max | Заголовок, текст, CTA, URL | Только когда это явно есть в брифе или выбранном исходном шаблоне |
| `bottom-nav` | Три ссылки-плашки | Подписи и URL | Только когда это явно есть в брифе или выбранном исходном шаблоне |

## Рецепты

### `promo-collection` — подборка туров

`header-nav → intro → [primary-cta] → divider → section-title → 3–8 tour-card (left/right по очереди) → divider → catalog-banner → [messenger-promo] → [bottom-nav] → footer`

Используй для акций, сезонных подборок, новинок и тематических туров. Одна карточка тура — это один URL: изображение, заголовок и CTA ведут на тот же URL.

### `promo-single` — одно предложение

`header-nav → intro → primary-cta → catalog-banner → [messenger-promo] → footer`

Используй, если письмо продвигает одну акцию или страницу, а не каталог.

### `digest` — несколько тем

`header-nav → intro → (section-title → 2–4 alternating cards) × 2–3 → catalog-banner → footer`

Не смешивай больше трёх тем в одном письме. Для каждой темы используй отдельный `section-title`.

## Поля карточки тура

Перед сборкой подготовь для каждой карточки ровно эти поля:

```text
Название тура:
Маршрут (одна строка):
Длительность и даты:
Изображение URL:
Alt изображения:
URL тура:
CTA (по умолчанию: «Узнать подробнее»):
```

Не выдумывай даты, цену, скидку, ссылку или изображение. Если поля нет, AI оставляет пометку для SMM, а не публикует ложное утверждение.

## Что можно написать AI без знания кода

```text
Собери письмо promo-collection.
Тема: Последние места на ноябрьские выходные.
Прехедер: Пять коротких поездок по России.
Главный CTA: Смотреть все туры — https://vs-travel.ru/podbor-tura
Кампания: november-weekends-2026.
Карточки: [вставляю 5 туров по форме].
Блок Max: не нужен.
```

AI сам выбирает подходящий исходник, чередует карточки, прописывает общие UTM и создаёт готовый HTML-файл. SMM не обязан открывать VS Code или вставлять блоки вручную. Хедер и футер — общая оболочка; любые промежуточные блоки добавляются только по смыслу брифа и выбранного шаблона.
